# 59 — Configuração privada do segredo OIDC local

Uma leitura de diagnóstico exibiu indevidamente o segredo fixo presente no arquivo de importação do laboratório. Correção26/10: cliente rancher16 rotacionado pela API administrativa local do Keycloak, novo valor mantido no .env existente e jamais incluído nos relatórios/saída. Introspecção com token sintético demonstrou segredo antigo recusado401 e novo aceito200/active=false. Somente esse cliente local foi rotacionado; nenhuma conta/grupo foi promovida ou senha de usuário live alterada.

realm.json agora usa ${OIDC_CLIENT_SECRET}; credenciais de usuários sintéticos usam ${LAB_USER_PASSWORD}. Compose injeta ambas no Keycloak; o backend recebe o mesmo segredo privado. Importação aceita callbacks das portas clássica18080 e console18090. Placeholder de ambiente é recurso documentado pelo [Keycloak](https://www.keycloak.org/server/importExport#_using_environment_variables_within_the_realm_configuration_files). Realm existente é preservado no startup; não foi reimportado/zerado.

Keycloak e Rancher foram recriados sobre seus volumes existentes, sem reset de dados, e reserva de IP Rancher .4 continuou válida. Relatório oidc-secret-rotation-results.json não contém segredo/token, só resultados. Readback concluído: login local e fluxo authorization-code OIDC autenticaram; contas comuns não foram promovidas; sem-acesso continua com zero environments. deploymentRestartPending=false no relatório. Rotação não é release de produção nem substitui revisão final REL05. Ferramenta rotate_local_oidc_secret.py é operação explícita de manutenção, não teste para rodar automaticamente em toda regressão.
